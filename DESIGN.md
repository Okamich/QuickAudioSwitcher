# QuickAudioSwitcher — Архитектурная спецификация и дизайн системы

Утилита быстрого управления и переключения аудиоустройств вывода для Windows 11.

---

## 1. Сводка понимания задачи (Understanding Summary)
* **Цель:** Устранить хаос и неудобство при переключении вывода звука в Windows 11 между колонками и двумя одинаковыми мониторами Xiaomi g24i (со встроенными выходами на наушники), скрывая технические и неиспользуемые выходы (Steam Streaming, Oculus, Realtek Digital и др.).
* **Ключевой функционал:**
  * Добавление устройств в **«Избранное»** (отображаются только выбранные).
  * **Решение проблемы одинаковых имен:** возможность задать понятные пользовательские имена (алиасы) для выходов (`Монитор Левый`, `Монитор Правый`, `Колонки`) и встроенная кнопка воспроизведения тестового сигнала (`▶ Тест`), чтобы определить физический монитор на слух.
  * **Два режима переключения:**
    1. *Через системный трей:* компактное всплывающее меню (Flyout) по клику у часов с переключением в 1 клик и ползунком громкости активного устройства.
    2. *Через глобальную горячую клавишу:* циклический перебор избранного с красивой ненавязчивой OSD-плашкой на экране (HUD).
  * **Фоновая работа:** тихое сворачивание в трей, автозапуск с Windows, мгновенный старт без мерцания консоли, потребление памяти ~15–25 МБ.
* **Не-цели (Non-Goals):**
  * Не реализуется микшер приложений (Volume Mixer для отдельных программ) или эквалайзер.
  * Не затрагиваются устройства записи (микрофоны).

---

## 2. Зафиксированные предположения (Assumptions)
1. **Тип переключаемого устройства:** переключаются одновременно `eMultimedia` (игры, видео, браузер) и `eCommunications` (Discord, Telegram, звонки).
2. **Технологический стек:** C# (.NET 8 SDK), нативный Win32/WPF с Dark Theme в стиле Windows 11, CoreAudio COM API (`IPolicyConfig`, `IMMDeviceEnumerator`).
3. **Формат сборки:** один легковесный автономный исполняемый файл `.exe` (Single-File).
4. **Хранилище настроек:** JSON-файл в `%APPDATA%\QuickAudioSwitcher\config.json`.

## 3. Полный журнал решений (Decision Log)

| № | Вопрос / Решение | Рассмотренные альтернативы | Обоснование выбора |
|---|---|---|---|
| 1 | **Формат взаимодействия:** Трей-меню + Хоткей с OSD | Только трей; только хоткей; плавающий виджет | Максимальное удобство: мышь для точной подстройки громкости и выбора, клавиатура для мгновенного переключения в играх. |
| 2 | **Идентификация мониторов-близнецов:** Пользовательские псевдонимы + кнопка «Тест звука» | Только ID в системе; только ручное имя без теста | Тестовый звуковой сигнал позволяет безошибочно определить «где левый, а где правый» на слух без гаданий. |
| 3 | **Управление громкостью:** Ползунок громкости в трей-меню | Без ползунка; ползунок у каждого выхода | Удобно сразу подправить громкость после переключения, не загромождая меню. |
| 4 | **Технологический стек:** C# .NET 8 / WPF | Python (CustomTkinter/PyQt) | Мгновенный запуск, <20 МБ ОЗУ, нативные COM-интерфейсы Windows, сборка в чистый `.exe` без внешних зависимостей. |
| 5 | **Отказоустойчивость:** `IMMNotificationClient` + `Mutex` | Опрос по таймеру (polling); несколько процессов | Подписка на системные события отслеживает спящий режим мониторов без траты ресурсов CPU; Mutex защищает от дублирования. |

## 4. Архитектура и структура компонентов

```
QuickAudioSwitcher/
├── Program.cs                     # Точка входа, Mutex, обработка аргументов
├── App.xaml / App.xaml.cs         # Контекст приложения, жизненный цикл
├── Core/
│   ├── AudioEngine.cs             # Взаимодействие с CoreAudio и IPolicyConfig COM
│   ├── AudioDevice.cs             # Модель аудиоустройства (ID, системное имя, алиас, статус)
│   ├── AudioTester.cs             # Генератор/проигрыватель тестового тона на конкретный выход
│   ├── HotkeyManager.cs           # Win32 RegisterHotKey / UnregisterHotKey
│   └── ConfigManager.cs           # Загрузка/сохранение конфигурации в %APPDATA%
├── UI/
│   ├── TrayController.cs          # Иконка в трее (NotifyIcon), контекстное меню
│   ├── FlyoutWindow.xaml(.cs)     # Быстрое меню над треем (избранное + громкость)
│   ├── OsdWindow.xaml(.cs)        # Полупрозрачная OSD-плашка при смене хоткеем
│   └── SettingsWindow.xaml(.cs)   # Окно настройки устройств, избранного и автозапуска
└── Resources/
    ├── AppIcon.ico                # Иконка приложения для трея и окна
    └── Styles.xaml                # Темная тема (Windows 11 Fluent Dark)
```

## 5. Детализация подсистем

### 5.1. AudioEngine (CoreAudio & IPolicyConfig)
* **COM-интерфейс `IPolicyConfig`:**
  ```csharp
  [ComImport, Guid("F8679F50-850A-41CF-9C72-430F290290C8"), InterfaceType(ComInterfaceType.InterfaceIsIUnknown)]
  interface IPolicyConfig {
      int SetDefaultEndpoint(string wszDeviceId, ERole eRole);
  }
  ```
  Позволяет переключить активный выход вызовом `SetDefaultEndpoint(deviceId, ERole.eMultimedia)` и `SetDefaultEndpoint(deviceId, ERole.eCommunications)` за < 15 мс без внешних процессов.
* **Громкость:**
  Используется `IAudioEndpointVolume` для считывания текущего уровня громкости (0.0–1.0) и мгновенного изменения при движении слайдера.
* **Слушатель отключений (`IMMNotificationClient`):**
  Уведомляет приложение об изменениях статуса устройств (например, отключение HDMI/DisplayPort при уходе монитора в сон), предотвращая попытки переключения на неактивный выход.

### 5.2. Пользовательский интерфейс (WPF Dark Theme)
* **FlyoutWindow:**
  * Располагается динамически над областью уведомлений (рядом с иконкой трея).
  * `ShowInTaskbar = false`, `WindowStyle = None`, `AllowsTransparency = true`.
  * Автоматически скрывается при событии `Deactivated`.
  * Список устройств с выделением активного галочкой / радио-индикатором.
  * Слайдер громкости с отображением процентов (0–100%).
* **OsdWindow:**
  * Полупрозрачное темное окно с закругленными углами в центре внизу экрана.
  * Win32-стили: `WS_EX_TRANSPARENT | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW` — не крадет фокус у активных приложений и игр.
  * Плавная анимация появления (Fade In) и угасания (Fade Out) с таймером в 1.5 секунды.
* **SettingsWindow:**
  * Таблица всех доступных аудиоустройств Windows с чекбоксами «В избранное», полями переименования и кнопками проверки звука.
  * Блок настройки горячей клавиши.
  * Переключатель «Автозапуск при старте Windows» (`Registry.CurrentUser.OpenSubKey(@"Software\Microsoft\Windows\CurrentVersion\Run", true)`).

## 6. План тестирования и проверки
1. **Обнаружение устройств:** проверка корректного считывания всех выходов из скриншота (Steam, Oculus, Realtek, 2x Mi Monitor).
2. **Проверка звука (Sound Test):** проверка, что воспроизведение направляется именно в выбранный `EndpointId`.
3. **Переключение:** валидация смены Default Device в Windows при клике и при нажатии горячей клавиши.
4. **Автозапуск:** проверка записи и удаления ключа реестра.
5. **Сборка:** компиляция `dotnet publish` и проверка работы автономного `.exe`.
